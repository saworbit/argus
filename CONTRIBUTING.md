# Contributing to Argus

Welcome, and thank you for your interest in contributing to **Argus**! 

Argus is an advanced deathmatch bot and telemetry laboratory for Quake 1, built in pure vanilla QuakeC. The project unites the heritage of classic bot innovations (such as the *Reaper Bot* and *Omicron Bot*) with modern empirical analysis, machine learning assisted navigation, and automated verification.

Whether you are improving bot combat AI, adding navigation support for new community deathmatch maps, tuning physics models, or refining lab tooling, we are excited to collaborate with you.

## Design Philosophy & Hard Constraints

Every subsystem in Argus is designed to run across any standard Quake engine without requiring special engine forks or proprietary extensions.

1. **Pure Vanilla QuakeC**:
   - Runs on standard NetQuake protocol 15.
   - Max 600 edicts ceiling.
   - Zero engine extensions, zero file I/O builtins.
2. **Empirical Telemetry Driven**:
   - Bot movement, aim curves, hazard avoidance, and combat decisions are validated through match telemetry (`ARGLOG` and `ARGEVT` streams) and A/B benchmark comparisons.
3. **Engine Compatibility**:
   - Must run identically on QuakeSpasm, Ironwail, vkQuake, FTEQW, DarkPlaces, and the official 2021 re-release (Kex engine).

## Development Setup

### Prerequisites

- **Python 3.10+**: For telemetry parsers, reachability checkers, and navigation generation.
- **Modern `fteqcc`**: Required to compile the QuakeC source tree (must be a modern build from the FTEQW project; apt svn3400 is too old).
- **Rust (optional, for lab tooling)**: Required for building `tools/argus_mcp` (the MCP server and local web GUI).
- **Quake Engine or LibreQuake**: To run and test bot matches.

### Compiling QuakeC

The QuakeC source is located in `src/`. The build definition is configured in `src/progs.src`.

```bash
# From the repository root
cd src
fteqcc
```

`progs.src` compiles the source and outputs `lq1/progs.dat`.
To update the playable game mod package, copy `lq1/progs.dat` to `game/argus/progs.dat`.

### Running the Rust Lab Suite

The lab suite includes regression tests against committed match tapes, parsing tools, and MCP protocols:

```bash
cargo test --manifest-path tools/argus_mcp/Cargo.toml --lib
```

### Running a Headless Smoke Match

You can run automated headless bot matches on Linux or Windows to verify stability:

```bash
# Example with QuakeSpasm dedicated server
quakespasm -dedicated 8 -game argus +developer 1 +deathmatch 1 +map lqdm2
```

Inspect `qconsole.log` (generated with `-condebug`) to ensure telemetry is flowing and no `Host_Error` or runaway loops occurred.

## Working with Navigation Graphs

Argus includes built-in navigation graphs for `dm2`, `dm3`, `dm4`, `dm6`, and `lqdm2`.

> [!IMPORTANT]
> **Never hand-edit `src/argus_nav_<map>.qc` directly.**
> Navigation files are generated by `tools/argus_navgen.py` or through the `argus-mcp` GUI wizard (`argus-mcp gui`).

### Adding Navigation for a New Map

1. Extract the `.bsp` file (e.g. `mymap.bsp`).
2. Run the navigation generator:
   ```bash
   python tools/argus_navgen.py mymap.bsp mymap src/argus_nav_mymap.qc nav_mymap.png --no-dispatcher --register
   ```
   * `--register` updates `src/argus_nav_dispatch.qc` and `src/progs.src` automatically.
3. Verify reachability:
   ```bash
   python tools/argus_reach.py mymap
   ```
4. Recompile with `fteqcc`.

## Core Engineering Rules & Gotchas

- **Lab Frametime (0.1)**: Dedicated headless servers run at `frametime 0.1` (id's `host_frametime` clamp), while listen servers run near 72 fps. Any time-dependent physics (drag, acceleration, timers) must be scaled against `frametime` and calibrated to remain bit-stable at `frametime 0.1`.
- **Client Channel Builtins**: Bots use `classname = "player"` to satisfy standard game logic, but cannot receive client network packets. Builtins like `stuffcmd`, `sprint`, and `centerprint` are shimmed in `src/defs.qc` (`if (client.ar_isbot) return;`).
- **Telemetry Formatting**: `bprint` is silent on empty dedicated servers. Use `dprint` for telemetry output and always run with `+developer 1`.
- **Traces in Geometry**: In QuakeC, `traceline` originating inside solid geometry returns `trace_fraction == 1` (`trace_allsolid`). Safe floor probing routines must check `trace_allsolid` explicitly to avoid mistaking interior solids for bottomless voids.

## Submitting Pull Requests

1. **Fork and Branch**: Create a feature branch from `main` (e.g. `feature/stair-climbing` or `fix/dm3-lift-wait`).
2. **Compile & Test**:
   - Ensure QuakeC compiles cleanly with `fteqcc` (producing an id-format output).
   - Verify `cargo test --manifest-path tools/argus_mcp/Cargo.toml --lib` passes.
   - Run a short match to verify that telemetry records cleanly without engine warnings.
3. **Open a PR**: Fill out the provided [Pull Request Template](.github/pull_request_template.md). Explain what changed, the rationale, and any telemetry observations.
